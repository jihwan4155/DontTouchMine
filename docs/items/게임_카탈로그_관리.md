# 게임 아이템 카탈로그 관리

Unity에서 `Assets/_Game/Content/Resources/Items/ItemCatalog.asset`을 선택한다.
설정 화면의 카테고리 목록과 매치 배정 후보는 이 에셋을 사용한다.

## 플레이 동작

- 방장이 플레이 설정에서 카테고리 하나 또는 `랜덤`을 선택한다. 기존 방 설정 동기화로 참가자에게 전달된다.
- 랜덤은 활성 카테고리 중 하나를 선택한다. 모든 플레이어는 같은 카테고리의 아이템을 받는다.
- 서버가 아이템 ID를 중복 없이 추첨해 각 플레이어에게 배정한다. 클라이언트는 전달받은 ID에 해당하는 프리팹을 표시한다.
- 현재 음식·음료 59, 생활용품 122, 공구·작업용품 31, 총기·폭발물 16, 판타지 소품 56개가 활성화되어 있다. 보류·부품·모형 34개는 비활성이다.
- 색상·형태 변형은 각각 별도 아이템 ID다. 같은 ID를 두 플레이어에게 배정하지 않는다.

## 카테고리 추가

1. `Categories`에 원소를 추가하고 `Id`와 `Label`을 입력한다. Id는 저장·동기화에 사용하는 값이고 Label은 화면에 표시할 이름이다.
2. 아래 `Items`에 아이템을 등록한다. 활성 아이템이 최대 플레이 인원인 6개 이상이어야 카테고리를 활성화할 수 있다.
3. `Enabled`를 켜고 **카탈로그 검증**을 누른다. 다음 플레이부터 카테고리 선택 UI와 랜덤 추첨에 자동 반영된다. 목록 순서도 에셋에서 조절할 수 있다.

콘텐츠 목표는 카테고리당 20개다. Inspector가 부족한 수를 표시한다. 현재 총기·폭발물은 4개가 부족하지만 6명 배정에는 충분하다.

## 아이템 추가·수정

- 해당 카테고리의 `Items`에 `Id`, `Display Name`, `Prefab`을 입력한다. 아이템 ID는 전체 카탈로그에서 유일한 영문·숫자·밑줄 1~16자로 지정한다.
- 프리팹은 `CarryableItem`, `Rigidbody`, 충돌체가 있는 게임용 프리팹을 사용한다. 현재 등록된 프리팹은 캐릭터 크기 이하로 조정되어 있다. 새 프리팹도 같은 크기 규칙으로 준비한다.
- 해당 아이템의 `Enabled`를 끄면 신규 배정에서 제외된다. 카테고리의 `Enabled`를 끄면 선택 UI와 랜덤에서 모두 제외된다.
- 표시 이름·프리팹 교체에는 코드를 수정할 필요가 없다. 배포한 ID는 유지하고, 변경한 카탈로그와 프리팹을 포함해 모든 참가자가 같은 버전으로 빌드한다.
- 추가 에셋을 기존 `ItemCollection.json`과 전시용 프리팹 생성 과정으로 준비했다면 `Tools > Game > Items > Import New Collection Items Into Catalog`로 새 항목만 합칠 수 있다. 이 메뉴는 이미 등록한 ID의 수정 내용·활성 여부·순서를 덮어쓰지 않는다.

## 구현 및 검증

- `ItemCatalogSO`: 편집 가능한 원본 데이터와 유효성 검사. Resources 에셋으로 빌드에 포함된다.
- `ItemCatalog`: Unity 의존성이 없는 런타임 데이터. 하드코딩된 임시 복제 목록을 제거했다.
- `PlaySettingsCategoryCatalog`: 활성 카테고리를 읽어 랜덤 선택지와 함께 표시한다.
- `PlaygroundMatchScene`: 실제 등록 프리팹을 비활성 상태로 준비하고 배정 ID, 배치 충돌 크기, 리플레이 참조를 연결한다. 실제로 배정·배치된 물건만 네트워크 상태에 들어간다.
- `ItemAssignmentSystem`: 기존 서버 추첨 흐름에서 카테고리를 고르고 후보를 하나씩 제거하며 중복 없이 배정한다.
- 테스트: 카테고리별 1~6명 배정, 랜덤의 단일 카테고리 선택, 데이터 추가·비활성화, 잘못된 ID·프리팹·수량, 실제 Playground에서 매치 세션 생성과 리플레이 포함 여부를 검증한다.

도감 HTML과 전시 씬은 생성 시점의 에셋 목록이다. 런타임 카탈로그를 편집한다고 이 정적 문서와 씬이 자동 재생성되지는 않는다.

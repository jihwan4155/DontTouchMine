# 멀티플레이 물리·퇴장·결과 상태 복구

## 관측과 범위

2026-09-09, 별도 노트북 3대의 참가자 영상에서 캐릭터 위치 보정과 공중에 남는 박스를 관측했다. 추가 제보는 강퇴 후 정지, 결과 화면의 소지 물건, 로비 복귀 후 박스 누락이다. 영상만으로 호스트 부하·패킷 지터를 배제할 수 없으므로 모든 순간이동의 원인을 확정하지 않는다.

## 변경

- CarryableItem 물리는 권한자에서 계산한다. 움직이는 물건의 위치·회전을 최대 10Hz로 기존 Fusion 상태에 반영하고 참가자는 kinematic Rigidbody.MovePosition/MoveRotation으로 0.1초 동안 보간한다. 기존 프리팹의 네트워크 필드 레이아웃은 변경하지 않는다.
- 처음 잠들었을 때 추적을 끝내던 경로를 교체한다. 받침 제거 시 주변 동적 강체를 깨우며, 다시 움직이거나 잠드는 물건도 전송한다. 정지 상태와 자세가 같으면 전송하지 않는다. 오래된 버전, 소지·파괴·보관 중인 물건의 물리 갱신은 거절한다.
- 강퇴 통지의 ACK 후, 또는 전송 연결 종료 후 다음 Unity 프레임에서 Runner를 종료한다. 호스트 종료를 기다리지 않고 기존 화면 복귀 흐름으로 이어지며 최초 강퇴 사유를 보존한다.
- 결과 무대에서 승자·패자 모두 소지 물건 렌더러를 숨긴다. 늦은 하이라이트 복원이 있어도 결과 화면 동안 숨김을 유지하고, 실제 매치 소유권·결과 판정은 바꾸지 않는다.
- 로비 Awake 시 실제 로비 물건을 보관하여 Fusion의 additive scene 병합 뒤에도 경기장 물건과 구분한다. 미리 숨겨 둔 로비 물건은 하이라이트 복원 대상에서 제외한다. 아바타 재생본 역시 별도 재생 트랙을 가진 소지 물건 렌더러를 중복 소유하지 않는다.

## 자동 검증

- EditMode: NetworkContractTests 및 ReplayVisualTests 113개 통과, 그래픽 컨텍스트가 필요한 1개 제외.
- PlayMode 5개 통과: 승자 소지 물건 숨김과 늦은 하이라이트 복원 재적용, 실제 강체의 받침 제거 후 각성·낙하, 참가자 보간 및 재집기, Fusion Single의 정지→재이동 상태와 오래된/소지 상태 갱신 거절, 연결 종료 후 Runner 자체 종료 및 강퇴 사유 보존 검증.
- 최초 종료 테스트는 테스트 구성에서 세션 시작 플래그를 빠뜨려 사유 검증이 실패했고, 실제 시작 상태를 설정한 재실행에서 통과했다.
- 전체 WebGL 빌드·공개 배포·다른 노트북 접속은 수행하지 않았다. Single 테스트는 실제 다중 접속 수용 검증을 대체하지 않는다.

## 배포 후보에서 확인할 항목

1. 동일 빌드로 별도 PC 3대 접속 후 상자 주변 이동·점프 및 쌓인 받침 집기/던지기. 세 화면에서 낙하와 최종 위치 비교.
2. 호스트가 방에 남은 상태에서 한 명 강퇴. 대상은 방 찾기로 복귀하고 나머지는 정상 플레이.
3. 승자와 패자가 각각 물건을 든 상태에서 종료. 결과 첫 화면부터 물건이 숨겨지는지 확인.
4. 하이라이트 재생/건너뛰기 각각 수행 후 로비 복귀 및 재경기. 호스트와 참가자 모두 박스 표시·상호작용 확인.
5. 캐릭터 보정이 지속되면 호스트 프레임 시간, RTT 변화, 패킷 손실 및 Fusion 재시뮬레이션을 함께 측정. 이번 물리 일치 수정만으로 네트워크 지연을 제거했다고 판단하지 않는다.

## 실행 순서와 검증 책임

Task 번호는 모두 GameProject 접두사를 사용한다. 570~579 시스템 작업 담당은 한태원이며 Spring 변경·검증은 백엔드 담당과 협업한다. 화면·에셋 제작은 기존 연결 Task 범위로 유지한다.

1. 570 정책·완료 기준 정리 및 미정 항목 답변 반영.
2. 574·579 변경 전 성능 측정. 실행 환경·빌드 해시·인원·데이터 기록.
3. 573 로비 리팩토링 → 576 정책 반영 → 738 규칙 편집.
4. 571 최종 맵·숨기기 → 736 공격 자세 → 737 시작 카운트다운 → 572 결과·HUD.
5. 574 게임·리플레이 병목 개선. 동일 조건 전후3회, Tick/프레임 p50·p95, GC·메모리·전송량·재생 준비시간 비교. 상위 병목1~2개만 개선, 병목 없으면 측정 결론 기록.
6. 577 기존 정확 검색 연동 검증 → 578 중복 요청·응답 역전 정리 → 579 API 병목 개선. 개발 환경 동시 사용자6→30→60, 지연·오류율·처리량·SQL·실행계획·CPU·커넥션 비교.
7. 739 신고 → 740 설정 공통 → 741 그래픽 → 742 오디오 → 743 조작 → 744 인터페이스 → 745 알림.
8. 575 최종 동일 버전 Windows 빌드6인 검증. 방 생성→로비→숨기기→탐색→결과→하이라이트→로비→재경기. 동시 집기·던지기·파괴, 개별/전체skip, 호스트 이탈·접속 실패도 검증.

573·574·578·579는 독립 Task로 유지한다. 측정과 개선을 서로 다른 신규 Task로 중복 산정하지 않는다. 신규 기능 변경은 feat/fix, 동작 유지 정리는 refactor로 구분한다.
